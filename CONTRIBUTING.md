# Contributing

Use a short-lived branch and keep each change focused.

Before opening a pull request:

1. Update the website brief or supporting documentation when scope changes.
2. Keep shared facts in site configuration and page copy in content modules.
3. Add or update tests for behavior, routes, metadata, and deployment paths.
4. Run pnpm verify.
5. Review the generated site at desktop and mobile sizes using real content.

Pull requests should explain the user-visible outcome, affected routes, verification
performed, accessibility impact, and any intentional deviation from the design system.
